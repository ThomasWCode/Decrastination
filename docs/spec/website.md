# The website

`https://decrastination.thomaswhite.me`, a React and TypeScript single-page app in `web/` (D-132), served by Caddy beside the API on one origin, so its session is an ordinary cookie and there's no CORS. A second client of the state the server holds (D-126). The server is in [server.md](server.md).

It holds no rule of its own (D-137). The server computes each page with the phone's own code (`engine/.../views/`: `DayViews`, `WorkViews`, `ChatViews`, `StatsViews`, `BackupViews`, `SetupViews`, from `DayModel`, `Groups`, `ChatRows`, `StatsPage`, `ReviewPage`, `BackupPage` and `SetupPage`) and sends it in the phone's words; the TypeScript lays it out. A change to how a day or a task reads is made once, in Kotlin.

Nothing is shown to the world: everything needs the owner's sign-in (D-128). It's read-only till the switch (D-141): while the server's mirroring the phone, each page says so by what it's sent, with nothing to press, as the phone's seeds are what change the state. Once it applies commands, the same pages can change things. A change is a command the page sends as the server gave it, or, where it takes the phone's rules to make one, a `TaskAsk`: what you gave, made into commands on the server (`TaskAsks`, `POST /api/tasks/{id}/ask`), so what a task allows and what's said of it are written once.

## The pages

- **Chat** (`/`, `web/src/Chat.tsx`, `ChatViews`), the home, as on the phone (D-121). The chat's window a message at a time, as `ChatRows` lays it: each day's line, the time under each message, his two texts as two bubbles, a quote where a reply isn't to the message above it, and "waiting for your answer". What he did is folded under his words, its line beside the fold and red where something went wrong: what he looked up, his cards, what he remembered and did, each with its Undo while it can be taken back. A page he looked up is a link only if it's http or https. Each message has Reply, Copy, a thumb up or down on his, with what you'd say of it and the pick of what he didn't send, and Mark answered where it waits, with an Undo for six seconds; the bar over the chat has Mark all answered and Clear the chat, which asks first. Yours waiting says why, with Try again and Take back, and while he's answering he's shown typing, with a Cancel after ten seconds. His question since your last turn is offered to the box, a strip that a ✕ turns down, and his replies are chips; a nudge just above the box takes your words as they are. Enter sends, and what's unsent stays through a move to another page. A chip's id is fixed, so a second press is the one message, and one that may have got there unheard goes again as itself. Scrolled back to its top, the archive's next page is read, 100 messages at a time, as the phone's are, with nothing to do on them; a quote follows its message back as far as it is (`GET /views/chat?earlier=&reach=`). His word on a review or on a week's summary has its own button, to the Reviews page. Your changes are beside the chat, not on a tab, as the page has the width for them, each with what's to do: a change to check, one in use to take back, one to write again. In mirror mode it's all there to read, the box with it gone: to write to him, the phone.
- **Day** (`/day`, `web/src/Day.tsx`, `DayViews`). Beside each other: a navy slab with the timer if one's running, Do now, what comes after it, the day's load and what's been done; and the week's strip over the day's time grid, a pixel to the minute till the wheel with Ctrl held changes that, which stays in the browser. Blocks overlap as they do on the phone: their columns are `DayLayout.columns`, sent with each block. `?date=` shows another day of the week. Do now has Start, Done with what it earned and its Undo, Later today, and All of it done on one of your own; what's the phone's own stays there (its source opened, a photo taken). A piece opens its sheet, and it, or a break outside still to come, can be dragged: a landing shows where it'll go, Escape puts it back, and the drop is judged by the server on the plan as it then is (`Moves.dropped`, the phone's own rule, `POST /day/drop`): on the grid its task's next piece at that time, on the week's strip all of its task that day, with what's said of it or why not. The grid's maths in the browser (`web/src/dayLayout.ts`) only shows where a block will land, and its cases are `DayLayout`'s own (`fixtures/web/day-layout.json`, read by a test on each side).
- **Work** (`/work`, `web/src/Work.tsx`). Every open task in columns, by due date or by subject, with a filter by source. Below them, what isn't planned and why, what's been hidden, what's finished, and how each source was last read. Work that looks the same is said, with Same and Different. New task opens the form (`NewTask.tsx`), whose kinds and limits are the server's. From a photo reads homework into tasks (`PhotoTasks.tsx`, `POST /api/photos/tasks`): the browser turns it upright and shrinks it, the server reads it outside any command, as a call can take a minute, one at a time as each is paid for (a second is turned away with a 409), and each task's checked in the form and kept only if it's added. It's there only with Claude on and its key on the box.
- **A task's sheet** (`web/src/TaskSheet.tsx`, `TaskViews`). What it is, when it's due, how long it takes and when it can start, each with a Change where it can be given one and an Undo or a Clear where there's one to take back; its steps, what's in the plan and why, your changes on it, and its notes. Done says what it earned, as the phone's does (`PieceSays`), with an Undo. Later today, Tomorrow, Move (a day of the fortnight, then this piece at a time or all of it that day, `Moves`), and what's only for your own: All of it done, Edit, Home only, Delete. What can't be undone at a tap asks first. Not on the website: a source's Open, Read again, Gmail's finish, a photo of the work. A task with no steps has a timer on its next piece, and each step still to do one of its own (Start, or Stop with its time), asked of the server so it counts as something done on the task, as on the phone.
- **Stats** (`/stats`, `web/src/Stats.tsx`, `StatsViews.of`). The record over two weeks, six or this term, a named period being all the page can ask for: its tiles, a bar a day against the busiest, the last week first and the rest folded, by subject, when you work (a row a weekday, a cell an hour, darker for more kept, and hatched as well as red where more were missed, so it isn't told by colour alone), what's been learned, and the period in full. The hours the slots suggest and each class's Forget ask first, in the phone's words. *Export the record as CSV* downloads the zip the phone shares (`GET /record.zip`).
- **This week** (`/week`, `web/src/Week.tsx`, `StatsViews.week`). The week's check-in as the phone's form asks it, or that it's done, and the latest review. Saving keeps it and sets off the week's review, as Felix's check-in in the chat does (`POST /week/check-in`). One that isn't kept says why, with what's typed still there. In mirror mode the check-in's the phone's.
- **Reviews** (`/reviews`, `web/src/Week.tsx`, `StatsViews.reviews`). Each review's note, each change with its Undo while it's still what the review left, what was tidied from Felix's memory with its own, and what came of an Undo said over the page. The week's summary has Send it, a link that makes the email in your mail app, nothing being sent from here, and Copy, as a long link can be cut short on the way.
- **Settings** (`/settings`, `web/src/Settings.tsx`, `SettingsViews`). The pages that are shared state: About you, Hours and windows, School, Planning, Felix, Claude, Sources, Notifications. What's on each comes from the server, each field with its kind, range and what it does, and only what's changed is sent. Those that can loosen blocking are marked †; armed, one that does waits its hours as on the phone, shown under Waiting with its Cancel and, once the server holds the secret, a parent's code, which goes with the change it allows (`ApplyChangeNow`). Sources takes the sign-ins (D-143), and says which it holds, never what they are; a field typed in and cleared takes nothing away. Claude's page has how hard it thinks and its recent calls, each to open. What stays the phone's is listed under the pages.
- **Backup** (`/backup`, `web/src/Backup.tsx`, `BackupViews`). All the app keeps as a file, the same one the phone writes, so either can read it, with what's to know of one as things stand. While the server's mirroring that's all there is. Once it applies commands: Import, the copies saved before a reset, each with its Restore, and each kind of reset, asking first in the phone's words. What came of any of them is said over the page.
- **Setup** (`/setup`, `web/src/Setup.tsx`, `SetupViews`). What the server couldn't read at its start, how each source reads, and Claude, each with whether it needs you, in the phone's words. While mirroring, the sign-ins and the key in use are the phone's, so what's said goes by how each source reads; after, by what's held here. It's marked in the bar while it needs you, by the phone's rule (`SetupPage.attention`, in `GET /views/notices`).
- **Phone** (`/phone`, `web/src/Phone.tsx`). A code to pair a phone with, what's paired, when each was last heard from, and revoking one, which asks first.

Each page says how fresh it is: "From the phone 5 min ago". In mirror mode the phone is where the state comes from.

## Staying current

`web/src/live.ts` fetches a page's view, then listens to `/api/events`. The server says the revision it's at on connecting, and each new one; a page fetches again when the revision moves, as the page comes back into view, and so after a dropped connection.

## What's told

Notices are in the page (W-9), and the phone keeps every notification. The bell in the bar and the tab's title count his unread messages (`GET /views/notices`, `Outbox.unreadOf`, the phone's own count), unless you're on the chat with the tab in front, reading them.

A browser can be told with its tab closed too (W-9): *This browser*, on Settings' Notifications page, there once the server applies commands and the box has its VAPID keys. Each browser asks for its own, of Felix's messages, a slot's start and a timer's zero, and for nothing till it does, as the phone tells you of all of it anyway. `web/public/sw.js` shows everything pushed, a page in front or not, as a browser can stop sending to a site whose pushes show nothing, and a tap goes to the page it's about. It's there only for this: it caches nothing. Signing out stops the browser being told, what it's still asking for too, as what's told goes with the session. It doesn't wait for that, as a browser's own prompt can stay open for as long as it's left. One that fails says so in the bar, and the page shows the browser as that left it, stopped.

The chat is read as on the phone (Q120): a visit is seen after three seconds in front, unbroken, or by a message of yours sent (`web/src/visit.ts`, the time from the view, `ChatRows.READ_AFTER_MS`). Only a seen visit reads what it showed, as it's left: the tab hidden, or another page. It sends `ReadChat` with the newest message's own moment, not this browser's clock, so nothing written since the page was drawn is read, and the server holds it to now, as the mark only goes up. A visit keeps the *New messages* line it opened with, as the view's own moves as the chat's read.

## The look

The phone's navy and paper, in CSS variables with a dark scheme, Atkinson Hyperlegible Next served from the site itself (the content security policy allows nothing else). Wide-screen first: the grid and the columns use the width a phone doesn't have.

## Testing

The chat's tests run against a stand-in for Claude (`web/e2e/claude-stand-in.mjs`), which each answers by the words of the message it's given. The test server is given a made-up key and the stand-in's address (`CLAUDE_STAND_IN`, read only by a test's server), so no test can reach Claude, whatever's in the machine's environment.

`web/`: `npm ci`, then `npm run lint`, `npm run test:unit` (vitest), `npm run build` and `npm run test:e2e`. The last is Playwright in Chromium (`npx playwright install chromium` once) against the fat JAR in test mode (`DECRASTINATION_TEST=1`: its own database, sign-in stubbed, refused on a domain), with the newest `fixtures/stores/` seeded as a phone would, under the live site's content security policy. It runs two servers, each with a database of its own: `reading` against one that mirrors, as the site does till the switch, and `writing` (`e2e/writes.spec.ts`) against one taken into commands by `POST /api/test/commands`, with a made-up parent code. `LOOK=<a folder> npx playwright test look` takes screenshots of each page in both schemes.
